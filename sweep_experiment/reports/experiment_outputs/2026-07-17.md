## 22:10 — Comparison baselines: SAVi-DNO (fair fix) + SlowFast-VGen + TTC

**Source:** implementation task (user: "implement SAVi-DNO, SlowFast-VGen, and
TTC for long-horizon; check if SAVi-DNO already exists").
**Run:** code only — no cluster jobs submitted yet.

### Finding: SAVi-DNO was already ported to LongCat, but as an ORACLE (leaked)
A prior agent built `comparison_methods/scripts/savi_dno_longcat.py` (1102 LOC:
differentiable flow-matching Euler, noise interpolation, latent/pixel loss,
2-GPU DiT split, PSNR/SSIM/LPIPS/FVD/FID, GT-cache, 14+14@48). This is why the
FVD I3D protocol + the PVDM/SAVi-DNO 256px GT track + PSNR headline exist.
**BUG:** its driver optimized the generation noise directly against `gt_01` =
the scored future `[48:62]` for `rollout_steps` Adam steps, then scored that.
That is ground-truth leakage → an oracle upper bound, NOT a fair baseline vs
AdaSteer (which adapts on pre-gen_start context only). The PVDM reference is
NOT structured this way (its `rollout_steps` are autoregressive segments where
noise adapted on an *observed* segment seeds the *next* prediction).

### Fix (user chose the fair leakage-free protocol)
Rewrote the SAVi-DNO driver: adapt the sequence-adaptive noise ONLY on an
observed history segment (predict `[34:48]` from `[20:34]`), then seed the
sampler with that adapted noise to predict the true unseen future `[48:62]`
WITHOUT optimizing against it. New `generate_with_optimized_eps()`; summary now
records `protocol=fair_streaming_observed_history`, `leakage_free=True`. Kept a
`--oracle-leak` flag (default OFF) that reproduces the old behaviour, clearly
labelled as an oracle upper bound (env `SAVI_ORACLE_LEAK=1`). Added geometry
passthrough + banner. Falls back to no-optimize if history < num_cond+num_gen.

### SlowFast-VGen (Temp-LoRA) — NEW, wired into the sweep harness
`lora_experiment/scripts/run_temp_lora_tta.py` (METHOD=temp_lora). Reuses the
tested LoRA inject/train/reset from run_lora_tta. Defining mechanism: Temp-LoRA
fast-learns SEQUENTIALLY (episodic memory) — warm-start streams (cond→next)
windows along the OBSERVED context, then per-rollout-chunk updates on its OWN
generated frames. Leakage-free (context + self-generated only; never future GT).
Short-horizon: the streaming warm-start is what distinguishes it from plain
LoRA-TTA (which trains once, jointly). Wired: METHOD case in run_sweep.sbatch
(no ES/aug/CLIP flags — runner doesn't accept them), `_METHOD_MAP` +
`_KEY_TO_ENV` (TEMP_LORA_*), time/mem estimates. Config
`sweep_experiment/configs/panda_1000v_temp_lora.yaml` (TEMP_LORA_R8, matches
LORA_R8 hypers; saves mp4s + VBench). Dry-run submit verified: env vars all map,
NO_SAVE_VIDEOS=0, COMPUTE_VBENCH=1, 22h/256G.

### TTC — NEW, LONG-HORIZON ONLY, standalone
`comparison_methods/scripts/ttc_longcat.py` + `sbatch/run_ttc_longcat.sbatch`.
Training-free pathwise correction: custom Euler loop (reuses the SAVi-DNO DiT
forward engine), at low-noise steps (sigma ≤ thresh) re-anchors appearance to
the FIRST cond frame (default appearance-only: shift per-frame channel spatial
means; `--ttc-full-latent` blends whole latent). Long geometry 14+79@14
(matches panda_longctx_1000v), pool via load_ucf101_video_list so ids align;
reuses common's evaluate_generation_metrics + OnlineFrechetAccumulator for
directly-comparable PSNR/SSIM/LPIPS/FVD/FID/VBench. Has `--no-correction`
baseline arm. **Honesty caveat logged in the file:** TTC's paper is T2V; the
sigma-threshold / cadence / weight knobs are an adaptation to LongCat
continuation and need cluster tuning/validation before paper numbers.

**Interpretation:** the "SAVi-DNO already documented with PSNR" lineage is now
