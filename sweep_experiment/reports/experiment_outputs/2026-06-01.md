   concurrently) will finish in ~15h wallclock; K10_RAND chunks ~6h each →

2. **Same-class neighbours despite `batch_method=sequential`:** For "Punch"
   eval video, all 4 neighbours are "Punch". For "MilitaryParade" eval, all 4
   are "MilitaryParade". This is **not** a bug — UCF-101 enumerates clips
   alphabetically by class in both eval (`ucf101_std_480p`) and pool
   (`ucf101_pool_max`), so `pool[i:i+K-1]` lands in the same class as the
   eval index. The `sequential` code does no similarity computation; UCF's
   structure aligns the result with similarity by accident.
